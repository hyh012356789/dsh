# 000 理念

> 本文件译自英文原文 [000-philosophy.md](../000-philosophy.md)。如有出入，以英文原文为准。

dsh-superagent 是一个框架，也是一种与智能体协作的方式。它的核心原则是：

**占用尽可能少的人类注意力，交付尽可能大的价值。**

项目的每个部分都以它消耗的注意力来衡量。一条消息、一个通知、一个问题、一项设置、一个面板元素、一段文档，都要消耗某人的注意力；每一处都必须带来超过这份消耗的价值，否则就会被去掉。

## 这对智能体意味着什么

- **只在被要求时行动，或只在书面规则允许时行动。** 只有直接指向智能体、并且来自团队所允许之人的请求才算数：此人要么在允许列表上，要么处在团队开放接受请求的会话中。没人要求的工作需要团队写下的规则，并且从只记录智能体原本会做什么的模式开始。
- **只在有人必须行动或能用到结果时开口。** 它确认请求一次，并说明将要做什么。工作期间保持沉默。当结果就绪、需要决策或无法完成时，它才再次发消息。消息简短，并发到提出请求的那个会话。
- **一次只问一个具体问题，** 以结构化形式提出，让问题真正抵达当事人，而不是埋在一份长报告里。
- **它按影响停下，而不是按投入停下。** 局部改动推进到可审查的结果为止。需要设计决策的改动，则带着一个清晰的问题停下。
- **它如实报告。** 草稿标明未完成，失败就报告为失败，绝不为了省去提问而绕过限制。

## 这对设计意味着什么

- **概念少。** 设计中只有领域概念（例如来源）及其具体实现（例如 GitHub 和飞书）。业务需求会成为其中某个概念的属性，或智能体遵循的一段提示词。设计不会为它新增概念。
- **设置少。** 当某个值几乎适合所有团队时，就用默认值代替设置。团队用文字描述的行为属于提示词文本，不是设置。
- **面板只显示需要人处理的内容。** 它首先列出等待人处理的事项。健康状态不占任何空间。
- **文档按顺序阅读。** 每篇编号文档只建立在它之前的文档之上，读者永远不需要尚未引入的概念。

## 责任

智能体会以你们团队每天都能看到的账号发表评论、提交 PR、给人发消息。它发出的每条消息都在消耗同事的注意力，而你要为此负责。智能体能做的事越多，其运营者对团队负有的谨慎义务就越大：

- **从窄开始。** 先从一个很短的允许列表开始，主动工作只做记录。等智能体原本会做的事看起来正确了，再放宽两者。
- **为减少噪音而调优。** 当智能体太吵时，把它的提示词改得更短更严格，或者暂停它。不要靠增加更多消息去解释噪音。
- **不要用它制造数量。** 批量 PR、群发消息和无谓的忙碌，给团队带来的成本大于收益。
- **对它的发言负责。** 阅读智能体以你的名义发布的内容；有错就改提示词。

目标是：在对的时间给出对的帮助，其他时间什么都不给。
