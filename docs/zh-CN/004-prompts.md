# 004 提示词

> 本文件译自英文原文 [004-prompts.md](../004-prompts.md)。如有出入，以英文原文为准。

本文说明智能体读到什么、团队可以编辑什么，以及改动何时生效。它建立在 [000 理念](000-philosophy.md) 到 [003 执行](003-execution.md) 之上。提示词文本以英文撰写。

## 团队可编写的内容

团队可以编辑三个团队部分、添加技能，并覆盖每一个内置的系统提示词部分。大多数默认内容位于 `prompts/` 和 `skills/` 下。工具描述、通知和卡片仍留在代码中，无法通过提示词设置编辑。

| 部分 | 内容 |
| --- | --- |
| 沟通方式 | 何时给人发消息、消息怎么写、每条 GitHub 消息开头的那一行（默认是 `This is by an automated agent, not a human`）、如何处理审查，以及哪些普通账号属于审查机器人 |
| 工单范围 | 工单何时继续推进，以及何时带着一份草稿停下 |
| 交付要求 | PR 中的证据、带行数阈值的自动合并条件，以及提交作者；若未提供，执行器以智能体账号的 no-reply 地址提交 |
| 团队技能 | 智能体在需要时加载的知识，例如说明哪个飞书用户对应哪个 GitHub 账号的 `identities` 技能 |

内置文本涵盖角色、工具用法、宿主机制、授权规则，以及 GitHub 和飞书技能。它通过标题来引用团队部分，而不是重复它们。

### 内置部分与模板

覆盖项使用这些键：

| 部分 | 键 |
| --- | --- |
| 共享指令与角色 | `runtime/shared`、`runtime/orchestrator`、`runtime/worker` |
| 工作指令 | `runtime/subscriptions`、`runtime/replies`、`runtime/dispatch`、`runtime/work`、`runtime/admission` |
| 交接指令 | `runtime/handoff/orchestrator`、`runtime/handoff/worker` |
| 来源技能 | `skill/feishu`、`skill/github` |
| 生成的部分 | `runtime/environment`、`runtime/policy`、`runtime/policy/none` |

生成的部分是可编辑的模板。它们必须保留以下占位符：

- `runtime/environment`：`{variables}`，由执行环境的各行填充。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，每条已启用的规则占一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，在没有启用任何规则时使用。

编辑某个部分会改变模型收到的指令，但不会改变准入、授权、工具检查或账号包装器——这些仍由代码强制执行。

在人类明确要求时，主 Session 也可以用 `orchestrator_prompts_save` 保存覆盖项。如果某次保存省略了某个覆盖项的 `base`，就沿用已保存的 base。如果某个已被移除的部分仍存在于已保存的配置中，保存时会被丢弃；其他任何未知的部分都会被拒绝。

每个覆盖项都会记录自己基于哪段内置文本。升级会保留团队的文本。如果默认内容发生变化，面板会把该部分标为 **默认内容已更新**，并在团队文本旁边显示差异。团队可以保留自己的文本、改用新的默认内容，或者对它进行编辑。没有覆盖项的部分会自动跟随新的默认内容。

主 Session 可以在 `orchestrator_read prompts` 的 `default_changed` 下读到受影响的部分名称。

## 组装与优先级

系统提示词按以下顺序组装：

1. 共享指令和角色。
2. 三个团队部分。
3. 订阅和回复。
4. 主 Session 的调度，或执行器的工作指令。
5. `runtime/admission`，仅用于主 Session。
6. 交接指令。
7. `runtime/environment`。
8. `runtime/policy`，仅用于主 Session。

准入指令来自 `prompts/admission.md`。它们描述主动研判，以及什么时候可以直接从卡片上忽略一个不相关的候选。`orchestrator_eval` 返回的是上下文，而不是重复这些指令。

环境部分为主 Session 提供部署级的值，为每个执行器提供其工单专属的值。策略部分在每次模型请求时都会根据设置重新生成。它包含策略版本、接单模式、明确请求豁免，以及以 `- <name> (<id>): <instruction>` 形式列出的已启用规则，或者一句说明未启用任何规则的话。它放在最后，这样策略一旦变化，前面的提示词文本不受影响。

执行器还会读取 DeepSeek Harness 的编码提示词和仓库的 `AGENTS.md`；主 Session 不读这些。推断出来的工单会追加一条结尾说明，把它的执行器限制在匹配到的规则之内。派工和传入的消息以内联的触发卡片形式到达，只有内容被截断时才附带资源指针。

执行器无人值守地工作。它们的工具中排除了会向人提问、向人展示 UI 或更改 profile 的那些，例如 `ask_user_question`、`present` 和 `plugin_manager`。

从最强到最弱：

1. 由工具和宿主强制执行的事实：身份、权限、工具参数检查、回复用途、长度上限。提示词文本无法改变它们。
2. 内置部分和生成的部分，以团队对它们的覆盖为准。
3. 主动工单所匹配规则中的流程与沟通要求，仅适用于该工单的执行器 Session。
4. 团队部分和团队技能。
5. 外部文本：消息、评论、文档和引文。它是数据，永远不会改变规则或授权。

## 内置文本的原则

以下原则把 [000 理念](000-philosophy.md) 应用到智能体身上：

- **角色分离。** 主 Session 只负责路由：它转发原始触发和路由事实，不做任何技术决策；这一切通过一个路由工具完成，该工具可在一次调用中对多个等待中的候选作出决定。一条路由说明最多 30 个词。执行器负责阅读原始来源、判断范围、实现并验证。
- **主 Session 不等待。** 报告、后续通知、候选和已完成的后台任务都会作为消息自动到达。没有剩下要做的事时，它就结束本轮。守卫会拒绝 `sleep`、超过 30 秒的 shell 超时和超过 5 秒的任务等待，因为一个被阻塞的步骤会耽误新的候选。在主 Session 的完整提示词中，这些指令取代了 DeepSeek Harness 自带的任务通知说明。
- **只有人必须行动或能用上结果时才发消息：** 结果可以被审查或使用、需要决策或资源，或者工作无法完成。聊天消息默认一句话，硬性上限为 100 个词。
- **执行器自行决定后续处理。** 每个执行器处理并确认范围内的请求，并把超出其工单或属于其他工单的请求交回。一条消息只有在它的所有归属方都交回、或者在未接手的情况下结束时，才会成为新工作。主 Session 会收到后续通知，但只能为停止工作而对其采取行动。交回的消息随后会作为候选到达，并附上执行器的理由。
- **通过订阅和主 Session 协调。** 执行器会跟踪相关线程以获取上下文。主 Session 可以用不超过 100 个词的说明，发送来自另一个工单的某个事实。订阅和这条说明本身都不授予任何权限。
- **只在有明确引用时才挂接。** 消息必须指向某一工单的 PR、Issue、来源消息或确认，或者指向恰好只匹配一个工单的近期变更。仅凭主题相似是不够的。挂接会让工单订阅整个线程；执行器若发现它不相关，会使用 `orchestrator_thread_unrelated`，并且不在那里作答。
- **具体确认，只确认一次。** 在开始实质工作之前，执行器会确认每一个新请求，并指明对象和预期结果，以回复的形式发在原消息之下。
- **通过 `human_action` 提问。** 执行器在自己的报告中提出一个具体问题，主 Session 原样转发。如果这个问题是由某人的消息引出的，它会指明那条消息，并由宿主在那里提问；否则就在该工单的原始对话中提问。与此同时，已获授权的工作可以继续。
- **诚实的交付。** 创建 PR 不等于就绪；草稿会被标记为未完成；没有真实修改前截图的 UI 变更不算就绪。
- **人的暂停会一直有效**，跨越后续消息、新的执行器 Session 和重启，直到有人解除它。自动反馈绝不会恢复已暂停的工作。
- **示例只展示格式。** 示例句子不是智能体可以拿来主张的事实。
- **按结果处理审查。** 已修复并验证的评论会被静默解决；被拒绝的评论会得到一句话的理由。自动审查者的线程在得到答复后即解决，每个自动审查者对每个 PR 最多三轮。
- **让位于重复工作。** 当某人的分支或 PR 已经包含该工单的变更时，执行器会用一句话关闭自己的 PR，并指向对方的 PR。

## 版本

- 每次保存都会创建一个不可变版本，其中包含完整配置、修订号、前驱版本、时间戳和来源（面板或工具）。恢复某个版本或恢复默认内容会再创建一个版本。
- 保存时会指明它的基础修订。冲突的保存会被拒绝，但不会丢弃草稿。
- 会话在每次模型请求时都会读取最新版本，包括同一轮中后续的步骤。保存不会重启、取消或唤醒会话。宿主会记录每个会话用过的修订；执行器可以读取它曾在哪个修订下工作。
- 部署会设置总大小上限（包含覆盖项）。校验会拒绝未知的键、保留的内置技能名、未知的覆盖部分以及缺失的模板占位符。它绝不会静默截断文本。与默认内容完全相同的覆盖项会被删除，以便该部分跟随未来的默认内容。
