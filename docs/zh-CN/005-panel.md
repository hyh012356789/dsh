# 005 面板

> 本文件译自英文原文 [005-panel.md](../005-panel.md)。如有出入，以英文原文为准。

在 DeepSeek Harness Web 的侧边栏中打开 **Superagent**，即可监管智能体。面板优先呈现需要人处理的工作，其次是系统健康状况和历史。本文建立在 [000 理念](000-philosophy.md) 到 [004 提示词](004-prompts.md) 之上。

## 三个问题

打开面板会按顺序回答三个问题：

1. 现在有需要我处理的事吗？
2. 系统是否健康，是否在做该做的事？
3. 一项工作的历史是怎样的，从触发、评估到工单？

## 标签页

标签页顺着工作流排列：**概览**、**来源**、**触发**、**评估**、**执行** 和 **设置**。在仓库和账号设置成功之前，概览会显示还缺什么，并链接到相应的设置。

| 标签页 | 显示内容 |
| --- | --- |
| 概览 | 需要处理的工单、系统问题、过去 24 小时的活动计数，以及执行器负载。每个区块都链接到它的详情页面 |
| 来源 | 来源状态、设置问题和非零计数。被过滤的触发和被丢弃的消息与概览使用同一个 24 小时窗口 |
| 触发 | 按已订阅、评估中、24 小时内新触发或全部线程筛选的线程。每个线程按从新到旧显示它的触发、决定和订阅 |
| 评估 | 决定，以及各自的原因和匹配的规则 |
| 执行 | 执行器状态、暂停处理，以及按进行中、待处理、工作中、等待触发或已结束筛选的工单。工单详情显示操作、授权、等待中的输入、订阅和派工 |
| 设置 | 来源、评估、执行、提示词和部署。每个分组都包含它的保存历史 |

### 阅读单条记录

被丢弃的消息会链接到它的工单；若没有工单，则链接到它的线程。来源页面会说明是它的对话消失了，还是来源不再监听它。

仍由执行器负责的人类后续消息会标为 **已投递给工单**，且不经过评估。线程还会显示交回原因和仅用于上下文的订阅。**重新评估** 可以把这条后续消息送往评估，也可以重试一次没有有效判定的触发：被其来源过滤掉的、评估不可用的，或者已投递却既没有停止决定、也没有执行器确认的消息。

工单详情显示发起它的触发、决定及原因、范围和策略版本。派工和次要细节折叠在直接操作之下。**重试** 可用于输入投递失败，或工单在受阻或失败的报告之后等待人处理的情况。已结束的工单显示诸如 **PR 已合并** 或 **被人工停止** 之类的结局。

## 设置分组

- **来源：**每个来源一张卡片，包含它的开关、字段和已验证的账号信息。GitHub 还提供针对新 Issue、PR、评论和默认分支 CI 的全部接收开关。轮询和读取上限在 **高级** 中。
- **评估：**策略版本和规则，然后是 **在每个来源上** 和评估设置。每个来源的标签页包含它的允许列表、成员同步、准入表和机器人列表。同步在启动时以及点击 **立即同步** 时运行。准入表区分接收范围、发送者的成员身份，以及消息是否面向智能体。评估设置选择接单模式、超时和研判模型。
- **执行：**工作者模型、并发数、目录根、准备命令和禁止调用的命令。点击一个可用变量即可把它插入准备命令。
- **提示词：** **编辑** 用于修改团队部分、内置部分和技能。**完整提示词** 显示组装后的文本，并与已保存的文本或默认内容作比较。**历史** 列出各个版本。被编辑过的内置部分会标记为已修改，并且可以重置；模板会列出它要求的占位符。

  一次升级如果改变了某个被覆盖的默认内容，就会把它标为 **默认内容已更新**。面板会在团队文本上方比较新旧默认内容。如果没有记录旧的默认内容，就比较团队文本和新的默认内容。选择 **保留我的文本** 或 **改用新的默认内容**。针对已移除部分的覆盖项会列在标签栏下方，并在下次保存时被删除。
- **部署：**启动问题（带 **重新检查**）、状态目录和机器上限。已保存的上限无需重启即可生效。DeepSeek Harness 的插件管理器也提供同一个页面。

## 搜索

页头的搜索按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。原始消息中缺失的飞书链接，只有在宿主于当前进程生命周期内读取过它之后才能被搜到。

搜索也能按 `#12` 或 GitHub URL 这类引用找到线程，并按标题或匹配的线程找到工单。

## 原则

1. **聚焦重要的事。** 每个元素都要回答三个问题之一，否则就删掉。数字只有在会改变监管者行为时才出现。
2. **定义精确。** 分类有可核查的定义，彼此互斥且覆盖全部情况，工单阶段就是如此。标签说明这一行在等谁、需要什么，而不是一个内部状态码。
3. **每个概念只有一处。** 来源状态放在来源；线程和触发放触发；决定放评估；工单放执行。设置按其配置的概念分组。概览只概括这些页面并链接过去，而不是再变成一个详情视图。
4. **领域结构。** 面板使用领域术语。内部标识符只出现在折叠的细节里，能解析出名称的地方就用名称代替标识符。
5. **诚实的状态。** 计数等于它所链接列表的长度，任何状态都不与其他事实相矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须是可行动的；一次性的网络错误还不够。待人处理的行直接给出对应操作。页面说明保持一句话，更多细节放进 (?) 提示。破坏性操作需要确认。
7. **控件一致。** 使用 DeepSeek Harness 的设计令牌和控件行为。同样的信息在整个面板里应当看起来一致。每个设置区块只有一条保存栏，仅在存在改动、正在保存或保存失败时才可见。
